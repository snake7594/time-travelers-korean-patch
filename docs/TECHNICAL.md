# 기술 노트

작업하며 알아낸 포맷과, 실기에서 돌아가게 만들기까지 막혔던 지점들을 적어 둡니다.
같은 게임이나 같은 엔진(레벨파이브)을 건드릴 사람에게 도움이 되길 바랍니다.

---

## 1. 파일 구조

```
Time Travelers.iso
├── PSP_GAME/SYSDIR/EBOOT.BIN      암호화된 ~PSP PRX  ← 절대 건드리면 안 됨 (5장)
├── PSP_GAME/USRDIR/TT1_PSP.CPK    폰트·메뉴·동영상 (평문 CPK, 117개 파일)
└── PSP_GAME/INSDIR/TT1MEM.DNS     스크립트·텍스트 (PGD 암호화, 그 안에 CPK)
```

* **CPK** — CRI 아카이브. `@UTF` 테이블 + CRILAYLA 압축.
  TOC 행은 28바이트, 오프셋은 `min(TocOffset, ContentOffset) + FileOffset`.
* **PGD** — DNS 파일 전체가 블록 암호화. KIRK CMD4/7. 블록 단위로 복호→수정→재암호.
* **XPCK** (`.xa`/`.xc`/`.xf`) — 레벨파이브 아카이브. 안에 IMGP 텍스처, FNTP 폰트,
  XPVB 정점 버퍼가 들어 있음.
* 레벨파이브 압축 헤더는 `(크기 << 3) | 방식` — 0 무압축, 1 LZ10, 3 허프만8.

### `.cfg.bin` (TIPS·튜토리얼·스태프롤)

```
u32 엔트리 수 / u32 문자열 테이블 오프셋 / u32 테이블 길이 / u32 문자열 수
엔트리[]: u32 이름 CRC32
          u8  파라미터 수
          u8  타입 (2비트씩, 낮은 쌍부터: 0=문자열, 1=숫자)
          u16 0xFFFF
          u32 파라미터[]   ← 문자열이면 테이블 상대 오프셋, 없으면 0xFFFFFFFF
0xFF 로 16바이트 정렬 → 문자열들 → 다시 0xFF 패딩
```

오프셋 위치를 알기 전에는 문자열을 원래 자리에 그대로 두고 넘치면 잘랐습니다.
구조를 읽고 나서는 테이블을 원하는 길이로 다시 만들고 오프셋을 옮길 수 있게 되어,
스태프롤 874자 · TIPS 목록 23자의 잘림이 사라졌습니다.
`cfgbin.parse()`는 **자기가 다시 만든 결과가 원본과 바이트 단위로 같을 때만** 구조체를
돌려줍니다. 디스크의 510개 파일 전부가 이 검사를 통과합니다.

### `.scn` (선택지)

문자열 테이블이 **세 개**(헤더 0x30 / 0x34 / 0x38) 있습니다. 하나만 고치면 선택지에
엉뚱한 문장이 나옵니다. 모든 문자열을 원래 오프셋·길이 그대로 두고 공백으로 채웁니다.

## 2. 한글 글꼴

게임 폰트는 4bpp IMGP(16색 RGBA4444 팔레트, 32바이트 타일)입니다. 한글 글리프는
**쓰이지 않는 한자 코드포인트의 자리에 직접 그려** 넣고, 문자표가 그 코드를 가리키게
합니다. 문자표는 이진 탐색되므로 **정렬을 유지**해야 합니다.

* 타일 테이블과 픽셀 블록은 인접해 있어 한 덩어리로 묶어 재배치합니다.
* 글자 크기는 14×14로 키웠습니다(원본보다 큼).
* `telop_player` / `telop_sp`에는 공백 글리프가 아예 없어 U+0020을 새로 추가했습니다.
* 폰트마다 필요한 글리프만 남기고 문자표를 다시 만들어 여유 슬롯을 확보합니다.

`verify_all.py`는 **차분 검사**를 합니다 — 문자표에 코드가 있는 것만으로는 부족하고,
그 자리의 비트맵이 원본과 실제로 달라야 한글로 인정합니다.

## 3. 메뉴 이미지

8bpp IMGP(256색 RGBA8888, 64바이트 타일). 라벨 사각형은 `.pbi`/XPVB 정점 버퍼에서
꺼냅니다(XPVB: 정점 20바이트 = float32 ×5 — u, v, x, y, 미사용).

라벨을 지울 때 인덱스 0으로 칠하면 안 됩니다 — 팔레트마다 0번이 투명하지 않습니다.
**해당 사각형에서 가장 많이 쓰인 인덱스**로 칠합니다. 글자는 그 라벨이 쓰던
알파 램프에 매핑하되, 작은 크기에서는 래스터라이저가 완전 불투명에 도달하지 못하므로
커버리지를 최댓값 기준으로 정규화해야 속 빈 글자가 되지 않습니다.

## 4. 동영상 (PSMF/PMF)

`psp/mov/` 아래 87개. 이 중 자막이 구워진 것은 5개입니다.

```
avant_title.pmf       64.0 MB  14,916프레임  8분 20초  ← 아방 타이틀
A01A_0040.pmf          5.6 MB   1,663프레임  ← 실제 오프닝
TTP_Opening.pmf        4.1 MB   1,799프레임  ← 데모/어트랙트
yokoku_chapter07.pmf   1.9 MB   1,020프레임  ← 7화 예고편
A01A_0000_0010.pmf     0.5 MB     495프레임  ← 오프닝 카드
```

컨테이너는 **2048바이트 팩 하나에 PES 하나**인 MPEG-PS입니다. 영상은 H.264
**Main@2.1, CABAC, B프레임 없음, 참조 1장, poc_type 2, GOP 59**.

### 여기서 막혔던 것들

**(a) 자막 구간 검출.** 획만 세면 애니메이션 선화가 전부 걸립니다. 자막은 수십 프레임
동안 고정되고 작화는 매 프레임 변하므로, 앞뒤 프레임과 교집합을 취해 살아남는 화소만
셉니다. 거기에 **글자 정렬 판정**(비슷한 크기 상자 4개 이상이 한 베이스라인에)을 더하면
인물 클로즈업·정지 컷이 걸러집니다. 자막은 타자기처럼 한 글자씩 나오므로, 경계는
"누적 최대 대비 급락"으로 잡습니다 — 프레임 간 비교로는 한 문장이 서너 개로 쪼개집니다.

**(b) PTS가 엉뚱한 프레임을 가리킴.** PES 헤더의 PTS는 "그 패킷에서 **시작하는**
액세스 유닛"에 적용됩니다. 컨테이너를 보존하려고 원본 헤더를 그대로 뒀더니, 재인코딩된
프레임은 크기가 달라 자리가 밀리면서 PTS가 다른 프레임에 붙었습니다. `avant_title`은
PTS 표시 1,011개 중 1,010개가 어긋났습니다. → 각 패킷의 PTS/DTS를 **그 패킷에서 실제로
시작하는 프레임에 맞춰 다시 씁니다**(원본과 같은 약 14프레임 간격).

**(c) 0바이트 패딩.** 원본 스트림은 연속된 0이 **3바이트를 넘지 않습니다.** 남는 공간을
영상 스트림 안에 0으로 채웠더니 71 KB짜리 0 덩어리가 생겼고, 디코더가 이걸 파싱하지
못해 재생이 멈췄습니다. → 남는 공간은 **0xBE 패딩 PES 패킷**으로 처리합니다. 원본도
같은 방식을 씁니다(`A01A_0040`에 58개). 패딩 패킷은 영화 전체에 고르게 분산합니다.

**(d) 원문 제거 비용.** 자막 구간마다 화면 아래 넓은 띠를 인페인팅으로 다시 칠하면
그 프레임들의 부호화 비용이 급증합니다. 고정 팩 그리드에서는 데이터가 제때 도착하지
못해 재생이 끊깁니다. → **일본어는 그대로 두고 한글을 화면 상단에** 얹습니다. 대개
하늘·천장 같은 평평한 영역이라 비용이 훨씬 적고, 나머지 화면은 원본과 동일하게 남습니다.

### 인코딩 설정

```
-profile:v main -level 2.1 -pix_fmt yuv420p (2-pass ABR)
x264: keyint=<원본 GOP>:no-scenecut:bframes=0:cabac=1:ref=1:no-open-gop:
      repeat-headers=1:aud=1:weightp=0:pic-struct:nal-hrd=vbr
```

`nal-hrd=vbr`이 프레임마다 pic_timing SEI를 넣습니다. **filler NAL(타입 12)은 넣으면
안 됩니다.** 컨테이너의 팩 헤더·SCR·오디오 패킷·시스템 헤더·파일 길이는 전부 원본
그대로 유지합니다.

빌드 합격 조건: filler NAL 0 · pic_timing SEI = 프레임 수 · PTS 불일치 ≤ 원본 ·
최장 연속 0 ≤ 8바이트 · 파일 크기 동일 · 비디오 PES 밖 변경 0바이트.

## 5. 실기 구동 — EBOOT를 건드리지 말 것

가장 오래 헤맨 문제입니다. **PPSSPP에서는 멀쩡히 돌아가는데 실기에서 메뉴 진입 전에
게임이 죽었습니다** (오류 코드 `C1-2858-3`, 특히 PS Vita Adrenaline).

원인: 실행 파일 내 메시지를 한글화하려고 PPSSPP가 덤프한 **복호화된 평문 ELF**를 그대로
ISO에 넣었던 것. 원본 `PSP_GAME/SYSDIR/EBOOT.BIN`은 **암호화된 `~PSP` PRX**입니다.
실기는 이걸 그대로 요구합니다.

```
원본 EBOOT 선두 : 7E 50 53 50 ...   ("~PSP")
잘못된 빌드     : 7F 45 4C 46 ...   ("\x7fELF")
```

→ 빌더가 EBOOT를 **원본 암호화 상태로 보존**하도록 고쳤습니다. 그 결과 실행 파일 안의
메시지 52개는 한글화되지 않지만, 실기에서 돌아가는 쪽이 우선입니다.

같은 교훈: **부팅 경로에 있는 파일은 원본과 바이트 단위로 같아야 합니다.**
xdelta를 만든 뒤 반드시 적용해서 결과물 해시가 일치하는지 확인하세요.

참고 사례: PS Vita Adrenaline의 `C1-2858-3`은 ISO 구조/부트 파일 이상일 때 보고됩니다.

## 6. 참고한 선행 작업

동영상 부분은 [snake7594/vc2-korean-patch](https://github.com/snake7594/vc2-korean-patch)
(『전장의 발큐리아 2』 한글 패치)의 접근을 참조했습니다. 특히 다음이 결정적이었습니다.

* x264 스트림을 실기 미디어 엔진이 받아들이게 하는 조건 — Main@2.1, B프레임 없음,
  참조 1장, weightp 없음, AUD + SPS/PPS 반복, HRD VUI + pic_timing SEI, filler NAL 금지
* 컨테이너(팩 헤더·SCR·오디오)를 바이트 단위로 보존한다는 원칙
* 남는 공간을 0바이트가 아니라 정식 패딩으로 처리한다는 점
